# 이터널 리턴 알리미 (디스코드)

30분마다 이터널 리턴 소식을 확인해서 **스킨 · 새 시즌 · 쿠폰 · 점검 · 패치노트** 소식만 디스코드 채널로 보내 줘요.
서버 없이 GitHub Actions로 돌아가고(무료), 설치할 패키지도 없어요.

디스코드에서 `/쿠폰`, `/스킨`, `/패치`, `/영상` 명령어와 쿠폰 직접 등록(`/쿠폰추가`)도 쓸 수 있어요 → [디스코드 명령어](#디스코드-명령어)
패치노트를 **실험체 / 아이템 / 변경사항**으로 나눠서 `/패치노트 블레어`처럼 골라 볼 수 있어요 (AI 한 줄 요약 포함) → [패치노트 요약](#패치노트-요약-패치노트)
공식 유튜브에 새 영상이 올라오면 **따로 정한 채널에 1~2분 안에** 올려 줄 수도 있어요 → [유튜브 새 영상 바로 알림](#유튜브-새-영상-바로-알림-다른-채널)
소식 종류별로 채널을 나눌 수 있어요 (알림 / 패치노트·핫픽스·점검 / 유튜브 / 스킨 영상) → [채널 나누기](#채널-나누기)

## 파일 구성

```
bot.py                                   알림 봇 (30분마다 실행)
.github/workflows/er-news.yml            알림 봇 예약 실행
register_commands.py                     디스코드에 명령어 등록 (처음 한 번)
.github/workflows/register-commands.yml  명령어 등록 실행용
worker.js                                명령어 봇 + 유튜브 바로 알림 (Cloudflare에 붙여넣음, GitHub에는 안 올려도 됨)
state.json, data.json                    (자동 생성) 보낸 기록 / 명령어용 모음 데이터
patchnotes.json                          (자동 생성) /패치노트용: 최근 패치 3개를 쪼개서 정리한 것 + AI 한 줄 요약
```

## 무엇이 오나요

**공식 홈페이지 패치노트 게시판** (playeternalreturn.com → 새소식 → 패치노트)

| 글 | 알림 |
|---|---|
| 패치노트, 핫픽스 | ✅ 항상. 본문 앞부분과 대표 이미지를 같이 보여 줌 → **패치 채널** |

- 공식 홈페이지가 2시간 넘게(4번 연속) 안 열리면, 그동안만 Steam의 패치노트·핫픽스 공지로 대신 보내요. 다시 열리면 공식 홈페이지로 돌아가고, 같은 패치를 두 번 보내지 않아요.
- 예전처럼 Steam 공지에서 받고 싶으면 Variables에 `PATCH_SOURCE` = `steam`.

**Steam 한국어 공지** (store.steampowered.com/news/app/1049590 에 올라오는 것)

| 공지 | 알림 |
|---|---|
| 쿠폰 코드가 들어 있는 공지 | ✅ 항상 (코드를 따로 크게 보여 줌) |
| 쿠폰 마감 24시간 전 | ⏰ 한 번 더 알림 (기한을 읽을 수 있는 쿠폰만, 처음부터 하루 안에 끝나는 쿠폰은 제외) |
| 서버 점검 안내 / 점검 완료 / 임시·긴급 점검 | ✅ 항상 → **패치 채널** |
| 패치노트, 핫픽스 | ⏭ Steam 것은 안 보냄 (위 공식 홈페이지에서 받음) |
| 제목에 `스킨`이 있는 공지 | ✅ (단, `당첨자`·`오류`·`이상 현상`이 들어간 건 제외) |
| 새 시즌 소식 | ✅ 새 시즌 번호(예: 시즌 14)가 처음 나온 날부터 **3주 동안** 그 시즌 공지 |
| 이모티콘, 만화, 지난 시즌 공지, '점검 이후 확률 변경' 같은 점검 관련 기타 안내 등 | ⏭ 안 옴 |

공지에 유튜브 영상이 붙어 있으면 링크를 같이 보내서 디스코드 안에서 바로 재생돼요.

**유튜브 이터널 리턴 한국 채널** (@EternalReturnKR, 쇼츠 포함)

- 제목이나 설명에 `스킨`, `시즌`, `미리보기`, `찾아옵니다` 가 있는 영상만 와요.
  스킨 쇼츠는 보통 `#신규스킨` 태그가 붙거나 설명에 "○○가 루미아 섬에 찾아옵니다!"라고 적혀 있어서 이걸로 잡아요.
- 제목에 `KEL`, `마스터즈`, `서포트 패키지`, `비하인드` 가 있는 대회·홍보 영상은 빼요.
- **설명에 쿠폰 코드가 있는 쇼츠·영상은 필터와 상관없이 쿠폰 알림으로 보내요.** 시즌 시작 전 D-7, D-3 쇼츠처럼 Steam 공지에는 없고 유튜브에만 올라오는 쿠폰이 있어요. 이 쿠폰도 `/쿠폰` 목록과 마감 하루 전 알림에 들어가요.
- `미리보기`는 신규 캐릭터 미리보기도 같이 잡아요. 싫으면 아래 설정에서 키워드를 바꾸면 돼요.
- **스킨 영상**(제목에 `스킨`, 설명에 "○○가 찾아옵니다"·`#신규스킨` 등. 신규 캐릭터 소개는 제외)은 **스킨 영상 채널**로 따로 보낼 수 있어요. 쿠폰이 들어 있는 영상은 스킨 얘기가 있어도 유튜브 채널로 가요(모두가 봐야 하니까).
- [유튜브 새 영상 바로 알림](#유튜브-새-영상-바로-알림-다른-채널)을 켜면 유튜브 영상은 이 알림 봇 대신 명령어 봇(Worker)이 **따로 정한 채널에 바로** 올려요. (같은 영상이 두 채널에 두 번 오지 않게 자동으로 정리돼요.)

같은 쿠폰이나 같은 영상이 여러 곳에 나와도 한 번만 보내요.

## 설치 (10분)

### 1. 디스코드 웹후크 만들기
알림 받을 채널의 톱니바퀴(채널 편집) → **연동** → **웹후크** → **새 웹후크** → **웹후크 URL 복사**

> 이 URL만 있으면 누구나 그 채널에 글을 쓸 수 있으니 코드에 직접 넣지 말고 아래처럼 Secret에 넣어요.

### 2. GitHub 저장소 만들기
1. 새 저장소 만들기 (**Public 추천**: 비공개 저장소는 Actions 무료 사용 시간에 한도가 있어요. 웹후크 URL은 Secret이라 공개돼도 안전해요.)
2. `bot.py`를 저장소 최상단에 업로드
3. **Add file → Create new file** 에서 파일 이름 칸에 `.github/workflows/er-news.yml` 을 그대로 입력하고, `er-news.yml` 내용을 붙여넣어 커밋
   (점으로 시작하는 폴더는 드래그 업로드할 때 빠지는 경우가 많아서 이 방법이 확실해요.)

### 3. 웹후크 URL 등록
저장소 **Settings → Secrets and variables → Actions → Secrets** 탭 → New repository secret
- Name: `DISCORD_WEBHOOK_URL`
- Secret: 복사한 웹후크 URL

여기까지 하면 기본 설정(위 표대로)으로 동작해요. 바꾸고 싶은 게 있을 때만 아래 4번을 해요.

> **알림도 봇 계정으로 올리고 싶으면** → [알림을 봇 계정으로 올리기](#알림을-봇-계정으로-올리기-추천). 웹후크 대신 봇이 직접 글을 써서, 모든 채널이 개발자 포털의 봇 프로필 하나로 통일돼요.

### 4. (선택) 설정 바꾸기
같은 화면의 **Variables** 탭 → New repository variable. 안 넣은 항목은 기본값을 써요.

| Name | 기본값 | 설명 |
|---|---|---|
| `MENTION` | (없음) | 쿠폰 알림 때 붙일 멘션. `@everyone` 또는 `<@&역할ID>` |
| `STEAM_KEYWORDS` | `스킨` | 제목에 이 단어가 있는 Steam 공지를 보냄. 쉼표로 여러 개. 예: `스킨,신규 캐릭터` |
| `STEAM_PATCH_KEYWORDS` | `패치노트,핫픽스,서버 점검,점검 안내,점검 완료,임시 점검,긴급 점검` | 제목에 이 단어가 있으면 제외 단어와 상관없이 보냄. 점검·패치노트를 끄려면 `none` |
| `STEAM_EXCLUDE` | `당첨자,오류,이상 현상` | 제목에 이 단어가 있으면 안 보냄 (쿠폰·점검·패치노트 공지는 예외) |
| `SEASON_WINDOW_DAYS` | `21` | 새 시즌 소식을 받을 기간(일). `0`이면 새 시즌 소식 끔 |
| `YOUTUBE_CHANNELS` | 이터널 리턴 한국 채널 | 채널 주소를 쉼표로 여러 개. `off`면 유튜브 알림 끔 |
| `YOUTUBE_KEYWORDS` | `스킨,시즌,미리보기,미리 보기,찾아옵니다` | 제목/설명에 이 단어가 있는 영상을 보냄 |
| `YOUTUBE_EXCLUDE` | `KEL,마스터즈,서포트 패키지,비하인드,슈퍼컵,Masters,내셔널 리그` | 제목에 이 단어가 있으면 안 보냄 (대회 영상) |
| `YOUTUBE_SHORTS` | `on` | `off`면 쇼츠 제외 |
| `COUPON_REMIND_HOURS` | `24` | 쿠폰 마감 몇 시간 전에 다시 알릴지. `0`이면 끔 |
| `PATCH_SOURCE` | `official` | 패치노트·핫픽스를 어디서 받을지. `official` = 공식 홈페이지 / `steam` = 예전처럼 Steam 공지 |
| `WORKER_URL` | (없음) | 명령어 봇(Worker) 주소. 넣으면 `/쿠폰추가`로 등록한 쿠폰도 마감 알림이 오고, 유튜브 바로 알림을 켰을 때 여기서는 유튜브 알림을 안 보내요 |
| `GEMINI_MODEL` | (자동) | `/패치노트` AI 요약에 쓸 Gemini 모델을 고정하고 싶을 때만. 예: `gemini-3.5-flash`. 비워 두면 쓸 수 있는 최신 Flash 모델을 알아서 골라요 → [패치노트 요약](#패치노트-요약-패치노트) |
| `YOUTUBE_NOTIFY` | `auto` | `auto` = 위처럼 자동 / `on` = 유튜브 바로 알림을 켜도 이 채널에도 계속 보냄 / `off` = 여기서는 유튜브 알림 안 보냄 |

키워드 칸에 `*`를 넣으면 전부 보내고, `none`을 넣으면 키워드로는 아무것도 안 보내요. 예를 들어 `STEAM_KEYWORDS`를 `none`으로 두면 Steam에서 스킨 공지는 빠지고 쿠폰·점검·패치노트·새 시즌 소식만 와요.

### 5. 실행 확인
**Actions** 탭 → 왼쪽 `이터널 리턴 알림` → **Run workflow** → `mode` 선택

1. **check** → 채널에는 아무것도 안 보내고, 지금 올라와 있는 공지·영상이 각각 ✅ 보냄 / ⏭ 건너뜀 중 무엇인지 실행 로그에 이유와 함께 찍어 줘요. 필터가 마음에 드는지 여기서 확인하세요.
2. **test** → 필터를 통과하는 최신 공지 1개와 영상 1개를 채널로 보내요. 오면 웹후크 연결 성공.
3. **normal** → 첫 실행은 지금 있는 공지·영상을 **기록만** 하고 알림은 안 보내요 (채널 도배 방지). `state.json`이 생기면 준비 끝.

이후로는 30분마다 알아서 돌아요. 실행 로그에서 무엇을 보내고 무엇을 왜 건너뛰었는지 볼 수 있어요.

## 디스코드 명령어

| 명령어 | 답장 |
|---|---|
| `/쿠폰` | 지금 쓸 수 있는 쿠폰 코드, 보상, 남은 기한 (기한 임박한 순, 직접 등록한 쿠폰 포함) |
| `/스킨` | 최근 스킨 공지·쇼츠 10개. 공지·영상 설명에서 뽑은 **캐릭터 이름**을 앞에 붙여 보여 줌 (예: **크레이버** 가보자고! 카우보이!) |
| `/스킨 캐릭터:블레어` | 그 캐릭터의 스킨 소식만 (최근 10개). 이름 칸에 글자를 치면 캐릭터 목록이 떠요. 별명(`뎁마`, `다이린`)이나 이름 일부(`코렐`)도 되고, 캐릭터 이름이 아니면 스킨 제목·설명에서 찾아요 |
| `/패치` | 최근 패치노트·핫픽스 10개 (공식 홈페이지 글) |
| `/패치노트` | 가장 최근 패치를 한눈에: 핵심 요약, 바뀐 실험체·아이템, 핫픽스 → [패치노트 요약](#패치노트-요약-패치노트) |
| `/패치노트 이름:블레어` | 그 캐릭터·아이템·변경사항이 바뀐 내용만 자세히 (한 줄 요약 + 원문 수치) |
| `/영상` | 최근 스킨·시즌 영상 10개 (맨 위 영상은 바로 재생) |
| `/쿠폰추가 코드 [기한] [보상]` | 쿠폰 직접 등록. 방송·커뮤니티에서 본 쿠폰처럼 봇이 못 잡는 걸 넣을 때. 기한을 넣으면 마감 하루 전 알림도 와요 → [설정](#5-쿠폰-직접-등록-쿠폰추가-켜기) |
| `/쿠폰삭제 코드` | 직접 등록한 쿠폰 지우기 (코드 칸에 등록한 쿠폰 목록이 떠요) |

알림 봇이 30분마다 모은 `data.json`을 Cloudflare 무료 서버(Worker)가 읽어서 답해요. PC를 꺼 둬도 동작해요.
모음은 알림 봇이 돌 때마다 쌓여요. **예전 것까지 채워 둔 `data.json`**(스킨 233개: Steam 스킨 공지 2023년 9월~, 유튜브 스킨 쇼츠·미리보기 2021년~ / 패치노트·핫픽스 40개 / 스킨·시즌 영상 60개)을 저장소 최상단에 올려 두면 처음부터 꽉 찬 상태로 시작해요. 올린 뒤에도 봇이 새 소식을 그 위에 계속 더해요.

**캐릭터 이름**: 실험체 이름 목록(나무위키 실험체 분류 기준)으로 제목에서 먼저 찾고, 없으면 공지 본문·영상 설명에서 찾아요. "신규 캐릭터 ○○ 미리보기" 같은 공지가 올라오면 새 캐릭터 이름도 자동으로 배워요.

> 명령어가 바뀌었으니(`/패치노트` 추가, `/스킨`에 캐릭터 칸 추가) 새 `register_commands.py`를 올리고 Actions에서 **디스코드 명령어 등록**을 한 번 다시 실행해 주세요. 다시 등록하기 전에는 새 명령어가 안 보여요.

**스킨 모음 기준**
- Steam: 제목에 '스킨'이 있는 공지. 단 스킨 박스 판매, 환불, 사용 제한, 교환권, 확률 같은 운영 공지는 뺌
- 유튜브: 제목에 '스킨'이 있거나, 설명에 스킨 소개 문구("○○가 루미아 섬에 찾아옵니다", `#신규스킨`, "특별/보너스/첫번째 스킨", "ER Pass 스킨" 등)가 있는 쇼츠·영상. 신규 캐릭터 소개와 대회 영상은 뺌

> 위의 알림 설치(1~5)를 먼저 끝내고, **새 `bot.py`와 `er-news.yml`로 한 번 실행해서 저장소에 `data.json`이 생긴 걸 확인**한 다음 진행하세요.

### 1. 디스코드 앱 만들기
1. https://discord.com/developers/applications → **New Application** → 이름(예: 이터널 리턴 알리미) 입력 → 만들기
2. **General Information** 화면에서 두 값을 복사해 둬요.
   - `APPLICATION ID`
   - `PUBLIC KEY`
3. 왼쪽 **Bot** → **Reset Token** → 나온 토큰 복사 (한 번만 보여 줘요)

### 2. 명령어 등록 (GitHub)
1. `register_commands.py`를 저장소 최상단에 올리고, **Add file → Create new file**로 `.github/workflows/register-commands.yml`을 만들어 내용을 붙여넣어요.
2. 저장소 **Settings → Secrets and variables → Actions**
   - **Secrets** 탭 → `DISCORD_BOT_TOKEN` = 복사한 봇 토큰
   - **Variables** 탭 → `DISCORD_APP_ID` = APPLICATION ID
3. **Actions** 탭 → 왼쪽 `디스코드 명령어 등록` → **Run workflow**
   로그에 `등록된 명령어: /쿠폰, /스킨, /패치, /패치노트, /영상, /쿠폰추가, /쿠폰삭제`가 나오면 성공

### 3. Cloudflare에 명령어 봇 올리기
1. https://dash.cloudflare.com 가입/로그인 → 왼쪽 **Workers & Pages** → **Create** → **Create Worker**(Hello World 시작) → 이름(예: `er-bot`) → **Deploy**
2. **Edit code** → 원래 코드를 전부 지우고 `worker.js` 내용을 붙여넣기 → **Deploy**
3. 그 Worker의 **Settings → Variables and Secrets** → **Add**로 두 개 추가하고 저장(Deploy)

   | 이름 | 값 |
   |---|---|
   | `DISCORD_PUBLIC_KEY` | 1번에서 복사한 PUBLIC KEY |
   | `DATA_URL` | `https://raw.githubusercontent.com/GitHub아이디/저장소이름/main/data.json` |

   > `DATA_URL`은 GitHub에서 `data.json`을 열고 **Raw** 버튼을 눌렀을 때 주소창에 뜨는 주소예요. 저장소가 Public이어야 읽을 수 있어요.
4. Worker 주소(`https://er-bot.내아이디.workers.dev`)를 복사해 둬요. 브라우저로 열었을 때 "명령어 봇이 동작 중이에요"가 보이면 정상이에요.

### 4. 디스코드와 연결
1. 개발자 포털 → **General Information** → **Interactions Endpoint URL** 칸에 Worker 주소를 붙여넣고 **Save Changes**
   - 저장이 되면 연결 성공이에요. "could not be verified" 오류가 나면 `DISCORD_PUBLIC_KEY` 값을 다시 확인해 주세요.
2. 왼쪽 **Installation** → Install Link를 **Discord Provided Link**로 두고, **Guild Install**의 Scopes에 `applications.commands`가 있는지 확인 → 위쪽 **Install Link**를 복사해서 브라우저로 열기 → 내 서버 선택
3. 디스코드 채팅창에 `/쿠폰`을 쳐 보세요.

### 5. 쿠폰 직접 등록 (/쿠폰추가) 켜기
직접 등록한 쿠폰은 Cloudflare의 무료 저장소(KV)에 저장돼요.
1. Cloudflare 왼쪽 **Storage & databases → Workers KV** → **Create** (이름 예: `er-bot`)
2. Worker(`er-bot`) → **Settings → Bindings** → **Add binding** → **KV namespace**
   - Variable name: `ER_KV` (철자 그대로)
   - KV namespace: 1번에서 만든 것 → 저장(Deploy)
3. 새 `worker.js` 내용을 **Edit code**에 다시 붙여넣고 **Deploy**
4. GitHub 저장소 **Variables** 탭 → `WORKER_URL` = Worker 주소 (`https://er-bot.내아이디.workers.dev`)
   → 알림 봇이 30분마다 직접 등록한 쿠폰을 가져가서 **마감 하루 전 알림**을 보내요.

사용 예
```
/쿠폰추가 코드:LUMIA2026 기한:11/30 보상:에어드랍 1개
/쿠폰추가 코드:SEASON14 기한:12월 3일 오전 5시
/쿠폰추가 코드:THANKYOU            ← 기한을 안 쓰면 30일 동안 /쿠폰에 보여요
```
- 기한은 `11/30`, `11/30 23:59`, `11월 30일 오전 5시`, `2026.11.30` 처럼 쓰면 돼요. 시간이 없으면 그날 23:59(한국 시간)까지로 봐요.
- 같은 코드를 다시 등록하면 새로 쓴 칸만 바뀌어요 (기한만 고치기 가능).
- **기본으로 서버 관리 권한이 있는 사람에게만 보여요.** 다른 사람도 쓰게 하려면 디스코드 **서버 설정 → 연동 → (봇 이름) → `/쿠폰추가`** 에서 역할이나 멤버를 추가하면 돼요.
- 등록 완료 메시지는 그 채널 사람들 모두에게 보여요. 잘못 넣었으면 `/쿠폰삭제`.

### 명령어 봇 문제 해결
- **"정보를 불러오지 못했어요"**: `DATA_URL`이 틀렸거나 저장소에 아직 `data.json`이 없어요. 주소를 브라우저로 열어 JSON이 보이는지 확인해 보세요.
- **"상호작용 실패" / 응답 없음**: Interactions Endpoint URL이 저장됐는지, Worker를 Deploy했는지 확인해 보세요.
- **명령어가 안 보임**: 2번 등록을 다시 실행하고 디스코드를 새로고침(Ctrl+R)해 보세요.
- **`/쿠폰추가`가 안 보임**: 서버 관리 권한이 없는 계정이면 안 보여요(위 5번 참고). 권한이 있는데도 안 보이면 2번 등록을 다시 실행해 주세요.
- **`/패치노트`가 "아직 패치노트를 다 못 읽었어"라고 함**: 저장소에 아직 `patchnotes.json`이 없어요. 새 `bot.py`·`er-news.yml`을 올리고 `이터널 리턴 알림`을 한 번 실행해 주세요.
- **"KV(ER_KV)가 연결되어 있지 않아요"**: 5번의 Variable name이 정확히 `ER_KV`인지, 저장 후 Deploy 했는지 확인해 주세요.

## 패치노트 요약 (/패치노트)

공식 홈페이지에 패치노트·핫픽스가 올라오면 알림 봇이 본문을 **실험체 / 아이템 / 그 밖의 변경사항**으로 쪼개서 `patchnotes.json`에 정리해 둬요 (최근 패치 3개, 핫픽스는 같은 패치에 묶음). 명령어 봇은 그 파일을 읽어서 답해요.

| 명령어 | 답장 |
|---|---|
| `/패치노트` | 가장 최근 패치 한눈에 보기: 글마다 핵심 요약, 바뀐 실험체·아이템 이름과 판결(🔺 무죄 = 상향 · 🔻 유죄 = 하향 · 🔸 판결 보류 = 섞임 · 🆕 신규 · 🗑️ 삭제), 그 밖의 변경사항, 핫픽스, 원문 링크 |
| `/패치노트 이름:블레어` | 그 이름이 바뀐 내용만: 판결(무죄·유죄)과 한 줄 요약 → 개발자 코멘트 → 원문 수치. 같은 패치의 모드 보정·핫픽스도 이어서 보여 줘요. 최신 패치에 없으면 지난 패치에서 찾아 줘요 |
| `/패치노트 이름:트윈보우` | 아이템·변경사항 이름도 돼요. 이름 일부(`트윈`)나 별명(`뎁마`)도 되고, 칸에 글자를 치면 목록이 떠요 |
| `/패치노트 이름:실험체` | 묶음 전체를 한 줄씩. `실험체`(= `캐릭터`) / `아이템` / `변경사항` / `핫픽스` |
| `/패치노트 버전:12.7` | 지난 패치 보기 (저장된 3개 중에서. `이름`과 같이 써도 돼요) |

**켜는 법**
1. 새 `bot.py`, `.github/workflows/er-news.yml`, `register_commands.py`를 저장소에 올려요.
2. **Actions → `디스코드 명령어 등록` → Run workflow** (`/패치노트` 추가)
3. Cloudflare Worker **Edit code**에 새 `worker.js`를 붙여넣고 **Deploy**
4. **Actions → `이터널 리턴 알림` → Run workflow** (mode: normal) 한 번. 저장소에 `patchnotes.json`이 생기면 `/패치노트`가 답해요.

`patchnotes.json` 주소는 `DATA_URL`에서 파일 이름만 바꿔서 알아서 찾아요. 다른 곳에 두려면 Cloudflare에 `PATCHNOTES_URL`을 넣으면 돼요.

**AI 한 줄 요약 (선택, 무료)**

키가 없어도 `/패치노트`는 원문을 정리한 것만으로 동작해요. 키를 넣으면 실험체·아이템마다 판결과 한 줄 요약, 글마다 핵심 요약이 붙어요.
요약은 **코렐라인 말투**(반말)로 쓰고, 상향이면 **무죄**, 하향이면 **유죄**, 섞여 있으면 **판결 보류**라고 해요. 예: `🔻 루치아 — 유죄. 레벨 당 체력이 깎였어.`

1. [Google AI Studio](https://aistudio.google.com/apikey)에서 API 키를 만들어요 (카드 등록 없이 무료 사용량 안에서 써요).
2. 저장소 **Settings → Secrets and variables → Actions → Secrets** 탭 → `GEMINI_API_KEY` = 그 키. (코드나 채팅에 붙여넣지 말고 Secret에만 넣어요.)
3. 다음 실행부터 최신 글 → 지난 글 순서로 요약이 붙어요.

- 무료 사용량을 아끼려고 **한 번 실행에 AI 요청을 4번쯤**만 보내요. 처음에는 30분마다 조금씩 채워져서 최근 패치 3개가 다 채워지는 데 한두 시간 걸려요. 그 뒤로는 새 글이 올라올 때만 AI를 불러요.
- 무료 사용량을 다 썼거나 키에 문제가 있으면 3시간 쉬었다가 다시 시도해요. 그동안에도 원문 정리는 그대로 보여요.
- 모델은 쓸 수 있는 최신 Flash 모델을 알아서 골라요. 고정하려면 Variables에 `GEMINI_MODEL` (예: `gemini-3.5-flash`).
- 잘 붙었는지는 **Actions → Run workflow → check** 로그의 `AI 요약(Gemini): 키 정상 …` 줄, 평소 실행 로그의 `AI 요약 완료: …` 줄로 볼 수 있어요.
- AI에 보내는 건 공개된 패치노트 글뿐이에요. Google 안내로는 무료 사용량으로 보낸 내용이 Google 제품 개선에 쓰일 수 있어요.

## 유튜브 새 영상 바로 알림 (다른 채널)

공식 유튜브(@EternalReturnKR)에 영상이 올라오면 **정해 둔 채널에 바로** 올려요.
- 유튜브가 새 영상을 Worker에 바로 알려 주는 방식(구독)이라 보통 **1~2분 안에** 와요.
- 그 알림을 놓쳐도 Worker가 **5분마다** 채널을 직접 확인해서 빠짐없이 보내요.
- YouTube RSS는 몇 시간씩 고장(404) 나는 일이 잦아요. 그럴 땐 예비 경로(채널 업로드 목록 + 영상 정보)로 확인해서 알림이 멈추지 않아요.
- 보내는 영상 기준은 위 [무엇이 오나요](#무엇이-오나요)와 같아요: 스킨·시즌 영상 + 설명에 쿠폰이 있는 영상(쿠폰 코드를 크게 보여 줌). 공식 영상을 **전부** 받고 싶으면 아래 4번에서 `YOUTUBE_KEYWORDS` = `*` 를 추가하세요.

> 위 디스코드 명령어 설치(1~5, 특히 **5번 KV 연결**)를 먼저 끝내고 진행하세요.

1. **유튜브 알림 받을 채널에 웹후크 만들기**: 그 채널 톱니바퀴 → 연동 → 웹후크 → 새 웹후크 → URL 복사
2. Worker → **Settings → Variables and Secrets** → **Add**
   | 이름 | 종류 | 값 |
   |---|---|---|
   | `YOUTUBE_WEBHOOK_URL` | Secret | 1번에서 복사한 웹후크 URL |
   | `MENTION` | Text (선택) | 쿠폰 있는 영상에 붙일 멘션. 예: `@everyone` |
   | `DISCORD_BOT_TOKEN` | Secret (추천) | 봇 토큰. 유튜브 알림 글도 개발자 포털 봇 이름·사진으로 |
3. Worker → **Settings → Trigger Events**(또는 Triggers) → **Add → Cron Triggers** → Cron 식에 `*/5 * * * *` (5분마다) → 저장
4. (선택) 영상 기준을 바꾸려면 2번처럼 `YOUTUBE_KEYWORDS`, `YOUTUBE_EXCLUDE`, `YOUTUBE_SHORTS`를 Text로 추가 (뜻은 위 설정 표와 같아요)
5. 새 `worker.js`를 붙여넣고 **Deploy** 했는지 확인
6. 브라우저로 `https://er-bot.내아이디.workers.dev/youtube` 를 열어서 상태 확인. 5~10분 뒤 다시 열었을 때 이렇게 보이면 끝이에요.
   ```
   유튜브 알림: 켜짐 (봇 계정으로 채널에 올림)
   스킨 영상: 스킨 영상 채널로 따로 올림 (봇 계정)   ← 스킨 채널을 안 정했으면 "유튜브 채널로 같이 올림"
   5분마다 확인: 동작 중 (마지막 기록 …)
     영상 목록: RSS 정상            ← RSS가 고장 나 있으면 "RSS 장애(HTTP 404) → 예비 경로…"
   바로 알림(YouTube 구독): 연결됨 (…까지, 자동 갱신)

   [지금 Cloudflare 서버에서 접속 테스트]
   RSS: …
   예비 경로(업로드 목록): 정상
   영상 정보: 정상
   디스코드 유튜브 채널 (봇 계정): 정상
   디스코드 스킨 영상 채널 (봇 계정): 정상

   [최근 영상 처리 상태]
   (영상 ID): 보냄 / 건너뜀(기준 밖) / 기록만(켜기 전 영상) / 다시 시도 중 …
   ```
   테스트 칸은 열 때마다 Cloudflare 서버에서 YouTube·디스코드에 직접 접속해 본 결과예요 (디스코드에 글이 올라가지는 않아요). `예비 경로`와 `영상 정보`가 정상이면 RSS가 고장 나 있어도 알림은 와요.
7. GitHub **Variables**에 `WORKER_URL`을 넣었는지 확인 (명령어 5번에서 넣었으면 끝). 이게 있어야 원래 알림 채널에 같은 영상이 또 오지 않고, Worker가 확인한 영상이 `/영상` `/스킨` 모음에도 들어가요.
8. (추천) GitHub **Secrets**에 `YOUTUBE_WEBHOOK_URL` = 1번 웹후크 주소(Worker에 넣은 것과 같은 값)도 추가
   → 디스코드가 Cloudflare 서버를 잠깐 막아서 Worker가 30분 넘게 못 보낸 영상을 GitHub 알림 봇이 이 채널로 대신 보내요. 안 넣으면 원래 알림 채널로 대신 보내요.

- 처음 켰을 때는 **켜기 전 6시간 안에 올라온 영상만** 보내고, 그 전 영상은 기록만 해요 (옛 영상 도배 방지).
- YouTube 구독 신청·갱신(며칠마다 만료)은 Worker가 알아서 해요. 따로 할 건 없어요.
- 영상 알림 채널을 원래 알림 채널과 같은 곳으로 하고 싶으면 1번에서 같은 채널 웹후크를 쓰면 돼요.

**문제 해결**
- 상태가 `꺼짐 (YOUTUBE_WEBHOOK_URL 없음)` / `꺼짐 (KV 바인딩 ER_KV 없음)`: 2번 / 명령어 5번 설정을 확인하고 Deploy.
- `5분마다 확인: 아직 기록 없음`: 3번 Cron Trigger가 저장됐는지 확인. 저장 후 5분 기다려야 해요.
- `예비 경로도 실패` / `영상 정보: 실패`: YouTube가 Cloudflare 서버 접속을 막은 경우예요. 상태 화면을 캡처해서 알려 주세요.
- `디스코드가 Cloudflare 서버 IP를 잠시 막음 (1015)`: Cloudflare 서버는 여러 사람이 같은 IP를 같이 써서, 디스코드가 그 IP를 잠깐씩 막을 때가 있어요. 내 설정 문제가 아니에요. Worker가 5분마다 (보통 다른 서버에서) 다시 보내고, 30분 넘게 안 되면 GitHub 알림 봇이 대신 보내요(위 8번).
- `디스코드 웹후크 주소가 틀렸거나 삭제됨`: `YOUTUBE_WEBHOOK_URL`을 다시 복사해서 넣고 Deploy.
- `바로 알림: 연결 대기 중`이 한참 계속됨: 5분 확인만으로도 영상은 와요(조금 늦을 뿐). Worker 주소를 브라우저로 한 번 열면 다시 시도해요.

## 알림을 봇 계정으로 올리기 (추천)

웹후크 대신 **봇 계정이 직접** 채널에 글을 써요. 내가 디스코드에서 글 쓰는 것과 같은 방식이라, 알림 채널·유튜브 채널·명령어 답장이 전부 같은 봇(개발자 포털 → Bot 탭의 이름·사진)으로 보여요. 이름을 눌러도 봇 프로필이 떠요.

> 디스코드 명령어 설치(위 1~4)를 먼저 끝내고 진행하세요.

1. **봇을 '글 쓰기 권한'으로 서버에 다시 초대**
   - 개발자 포털 → 내 앱 → **Installation** → **Guild Install**
     - Scopes: `applications.commands` 와 **`bot`** 둘 다
     - Permissions: **View Channels**, **Send Messages**, **Embed Links** (멘션을 쓰면 **Mention Everyone**도)
   - **Save Changes** → 위쪽 **Install Link** 복사 → 브라우저로 열기 → 내 서버 선택 → 승인
   - 서버 멤버 목록에 봇이 보이면 성공
2. **채널 ID 복사**: 디스코드 **사용자 설정 → 고급 → 개발자 모드** 켜기 → 알림 채널을 우클릭 → **채널 ID 복사**. 유튜브 알림 채널도 똑같이.
3. **GitHub** 저장소 **Variables** 탭
   | 이름 | 값 |
   |---|---|
   | `DISCORD_CHANNEL_ID` | 알림 채널 ID |
   | `DISCORD_VIDEO_CHANNEL_ID` | 유튜브 알림 채널 ID |

   패치노트·점검, 스킨 영상을 다른 채널로 나누려면 → [채널 나누기](#채널-나누기)

   (봇 토큰 `DISCORD_BOT_TOKEN` Secret은 명령어 등록 때 넣은 걸 그대로 써요)
4. **Cloudflare Worker** → Settings → Variables and Secrets
   | 이름 | 종류 | 값 |
   |---|---|---|
   | `DISCORD_VIDEO_CHANNEL_ID` | Text | 유튜브 알림 채널 ID |
   | `DISCORD_BOT_TOKEN` | Secret | 봇 토큰 (GitHub에 넣은 것과 같은 값) |
5. **비공개 채널이면**: 채널 설정 → 권한 → 봇 추가 → 채널 보기·메시지 보내기·링크 첨부 허용
6. **확인**
   - GitHub Actions → `이터널 리턴 알림` → Run workflow → **test** → 알림 채널에 봇 이름으로 글이 오면 성공
   - 브라우저로 `Worker주소/youtube` → `유튜브 알림: 켜짐 (봇 계정으로 채널에 올림)`, `디스코드 유튜브 채널 (봇 계정): 정상`

- 채널 ID와 봇 토큰이 있으면 웹후크보다 먼저 써요. 잘 되는 걸 확인한 뒤에는 채널의 웹후크를 지워도 돼요. `DISCORD_WEBHOOK_URL`, `YOUTUBE_WEBHOOK_URL`도 그때 지워도 돼요.
- **"봇이 그 채널에 글을 못 써요 (403)"**: 1번 초대에서 `bot`이 빠졌거나, 채널 권한에서 봇이 막혀 있어요.
- Cloudflare 서버 IP를 디스코드가 잠깐 막는 일(1015)은 봇 계정이어도 똑같이 생길 수 있어요. 그때는 Worker가 5분마다 다시 보내고, 30분 넘게 안 되면 GitHub 알림 봇이 봇 계정으로 대신 올려요.

## 채널 나누기

소식 종류별로 채널을 따로 둘 수 있어요. **전용 채널을 안 정한 종류는 아래 '없으면' 채널로 가니까, 필요한 것만 넣으면 돼요.**

| 채널 | 오는 것 | 설정 이름 (채널 ID) | 없으면 |
|---|---|---|---|
| 알림 채널 | 쿠폰, 쿠폰 마감 알림, 새 시즌 소식, Steam 스킨 공지 | `DISCORD_CHANNEL_ID` | (필수) |
| 패치 채널 | 패치노트, 핫픽스, 점검 안내·완료 | `DISCORD_PATCH_CHANNEL_ID` | 알림 채널로 |
| 유튜브 채널 | 시즌 영상, 쿠폰이 있는 영상 등 스킨 영상이 아닌 것 | `DISCORD_VIDEO_CHANNEL_ID` | 알림 채널로 |
| 스킨 영상 채널 | 유튜브 스킨 쇼츠·미리보기 | `DISCORD_SKIN_CHANNEL_ID` | 유튜브 채널로 |

**넣는 곳** (채널 ID는 채널 우클릭 → 채널 ID 복사)

| 어디 | 넣을 것 |
|---|---|
| GitHub → Settings → Secrets and variables → Actions → **Variables** | `DISCORD_PATCH_CHANNEL_ID`, `DISCORD_SKIN_CHANNEL_ID` (원래 있던 `DISCORD_CHANNEL_ID`, `DISCORD_VIDEO_CHANNEL_ID`는 그대로) |
| Cloudflare Worker → Settings → Variables and Secrets (Text) | `DISCORD_SKIN_CHANNEL_ID` → 저장 후 **Deploy** |

- 패치 채널은 GitHub 알림 봇만 써요(Worker에는 안 넣어도 돼요). 스킨 영상 채널은 유튜브를 올리는 Worker와, Worker가 못 보낸 영상을 대신 올리는 GitHub 봇 **둘 다**에 넣어야 해요.
- 새 채널이 비공개면 채널 권한에서 봇에게 채널 보기·메시지 보내기·링크 첨부를 허용해 주세요.
- 웹후크로 쓰고 있으면 채널 ID 대신 웹후크 주소를 Secret으로 넣어요: `PATCH_WEBHOOK_URL`(GitHub), `SKIN_WEBHOOK_URL`(GitHub·Cloudflare).
- **확인**: GitHub Actions → `이터널 리턴 알림` → Run workflow → **test** 로 돌리면 패치 채널에 최신 패치노트 1개, 알림 채널(또는 패치 채널)에 Steam 공지 1개가 와요. 스킨 영상 채널은 `Worker주소/youtube` 를 열어서 `스킨 영상: 스킨 영상 채널로 따로 올림`, `디스코드 스킨 영상 채널 (봇 계정): 정상` 이 보이면 돼요.
- Actions를 **check** 로 돌리면 보내지는 않고, 로그에 어떤 글이 어느 채널로 갈지(`→ 패치 채널`, `→ 스킨 채널`)만 보여 줘요. `── 공식 홈페이지 패치노트·핫픽스` 목록이 보이면 공식 홈페이지 연결도 된 거예요.
- 유튜브 채널에 **스킨 영상만** 받고 싶으면(시즌 영상 등은 끄기) Cloudflare와 GitHub 둘 다 `YOUTUBE_KEYWORDS` = `스킨,찾아옵니다` 로 바꾸면 돼요. 쿠폰이 있는 영상은 그래도 와요.

## 말투 (코렐라인)

봇이 하는 말은 코렐라인 말투예요 (반말, "후후훗", 거울·빛·진실·유죄 같은 표현). 게임 대사를 그대로 베낀 게 아니라 그 말투로 새로 쓴 문구예요. 쿠폰 코드·기한·링크 같은 정보는 그대로 나와요.

문구는 두 곳에 모여 있어서 거기만 고치면 돼요.

| 파일 | 위치 | 무엇 |
|---|---|---|
| `bot.py` | 위쪽 `TONE = {` | 알림 채널 글: 새 쿠폰, 쿠폰 마감 알림, Steam 공지 한마디(점검·패치노트·핫픽스·스킨·새 시즌), 유튜브 알림 |
| `worker.js` | 위쪽 `const TONE = {` | 명령어 답장(`/쿠폰` `/스킨` `/패치` `/패치노트` `/영상` `/쿠폰추가` `/쿠폰삭제`), Worker가 올리는 유튜브 알림 |

- 따옴표 안 문장만 바꾸면 돼요. 한 종류에 문구가 여러 줄이면 그중 하나를 골라 써요. 줄을 더하거나 빼도 돼요 (줄 끝 쉼표 `,` 는 그대로).
- `{codes}` `{code}` `{hours}` `{channel}` `{kind}` 같은 중괄호 칸은 실제 값이 들어가는 자리라 지우면 안 돼요.
- 고친 뒤 `bot.py`는 GitHub에 올리고, `worker.js`는 Cloudflare **Edit code**에 붙여넣고 **Deploy**.
- 명령어 목록에 보이는 설명(`/쿠폰` 옆 회색 글씨)은 `register_commands.py`에 있고, 바꾸면 **디스코드 명령어 등록**을 다시 실행해야 해요.
- `/패치노트`의 판결 문구(무죄 / 유죄 / 판결 보류 …)는 `worker.js` `TONE`의 `verdictBuff` `verdictNerf` `verdictAdjust` … 에 있어요.
- `/패치노트`의 **AI 요약 말투**는 `bot.py`의 `_AI_RULES` 안 "말투 규칙"에 적혀 있어요 (AI에게 시키는 글). 고친 뒤 그 위의 `AI_STYLE` 숫자를 1 올리면, 이미 만들어 둔 요약도 다음 실행부터 새 말투로 다시 써요.

## 내 PC에서 돌려 보기

```bash
# macOS / Linux
export DISCORD_WEBHOOK_URL="웹후크 URL"
python bot.py --check       # 보냄/건너뜀 목록만 (웹후크 없어도 됨)
python bot.py --test        # 필터 통과하는 최신 공지·영상 1개씩 전송
python bot.py               # 평소 실행
```

```powershell
# Windows PowerShell
$env:DISCORD_WEBHOOK_URL="웹후크 URL"

```

## 알아 둘 점

- Steam 한국어 공지는 **Steam 상점 뉴스 페이지가 내부적으로 쓰는 주소**에서 가져와요. 공식 API가 아니라서 Steam이 페이지 구조를 바꾸면 깨질 수 있어요. 그러면 Actions가 실패로 표시되고 GitHub에서 메일이 와요.
- 유튜브 RSS는 몇 시간씩 404가 날 때가 있어요. 그럴 땐 알림 봇도 Worker도 예비 경로(YouTube 내부 주소)로 확인해요. 예비 경로는 공식 API가 아니라서 YouTube가 바꾸면 깨질 수 있어요 (RSS가 정상일 땐 안 써요).
- 유튜브 바로 알림은 올라온 지 이틀이 지난 영상은 보내지 않아요 (옛 영상 제목 수정 같은 걸로 다시 오는 걸 막으려고).
- Cloudflare 무료 플랜 한도(하루 요청 10만 번, KV 쓰기 1천 번) 안에서 넉넉히 돌아가요.
- 쿠폰 코드가 이미지에만 있거나 방송에서만 공개되면 코드를 못 뽑아요.
- `/패치노트`의 판결(무죄·유죄)과 한 줄 요약은 AI(Gemini)가 붙인 거라 틀릴 수 있어요. 수치는 항상 원문 그대로 같이 보여 주니 그쪽이 기준이에요. 패치노트 글의 모양(제목·굵은 글씨·목록)을 보고 쪼개기 때문에, 공식 홈페이지가 글 모양을 크게 바꾸면 분류가 어긋날 수 있어요.
- 필터에 걸려 건너뛴 공지·영상은 나중에 키워드를 바꿔도 다시 오지 않아요.
- 공개 저장소는 **60일 동안 활동이 없으면 예약 실행이 꺼져요.** 새 공지가 올 때마다 `state.json` 커밋이 생겨서 보통은 괜찮지만, 꺼지면 Actions 탭에서 다시 켜 주면 돼요.
- GitHub 예약 실행은 몇 분씩 늦게 돌 때가 있어요.
